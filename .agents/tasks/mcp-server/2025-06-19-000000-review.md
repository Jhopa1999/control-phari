# MCP server (apps/mcp) over stdio, 1:1 with the OpenAPI contract

The branch `feat/mcp-server` adds a new private workspace `apps/mcp` (`@plantilla-portales/mcp`) that exposes a Model Context Protocol server over stdio, built on the pinned official SDK (`@modelcontextprotocol/sdk@1.32.1`) and `zod@4.6.7`. It is a thin layer: 35 tools map 1:1 to real routes of `apps/api/openapi/openapi.json`, each delegating to the typed `@plantilla-portales/api-client` and translating API errors to MCP results. Identity is resolved from env vars (dev-header or jwt), login is lazy, and the only hard-coded domain exception is the login body (which the contract does not type). The change also appends `build:mcp`/`typecheck:mcp` to the root aggregates and includes an approved api-client ESM resolution fix.

Watch for: nothing blocking. One informational note on the second local enum (`process.list` `kind`) that lacks the equivalence safeguard applied to `objectType` (possible). The `plan-view.tsx` entry in `git diff main` is **not** a branch change (confirmed) and is out of scope.

**Verdict**: APPROVED

## High-level view

The architecture is faithful to the approved design. `config.ts` fails fast only on missing config and never performs network I/O; `api.ts` registers a single-header identity middleware (never both `X-Actor-Id` and `Authorization`) and keeps the JWT in memory only, with lazy login and a single reactive relogin on 401 restricted to the credentials path. Success of every call is `result.error == null`, never a status code, which correctly handles login's 200.

The tool surface is 35 tools grouped by module (health/identity, catalog, process, user, grant, request, plan+task, audit, portfolio), each a 1:1 wrapper over a verified contract route. Request/response bodies for create/update are delegated to the backend (`z.record` + cast to the contract DTO), so no domain validation leaks into the MCP; path/query params are reflected with zod. The `audit.events.list` `objectType` enum carries a bidirectional compile-time equivalence guard that intentionally breaks `typecheck:mcp` if the contract diverges.

Integration into the root `package.json` adds `build:mcp` and `typecheck:mcp` and appends mcp last to the `build` and `typecheck` aggregates; `workspaces` and all existing scripts are untouched. The api-client change (adding `.js` extensions and switching to `nodenext`) is a module-resolution fix needed because the MCP is the first consumer to run api-client's ESM output under Node; it changes no public contract and the aggregate typecheck confirms the frontend is not broken.

Verification is green end to end: `build:api-client`, aggregate `typecheck` (api → api-client → web → mcp), `build:mcp`, 31 unit tests, and a stdio smoke returning 35 tools all with `type: object` input schemas.

### Identity resolution and lazy login

`config.ts` validates presence only and `process.exit(1)`s to stderr on missing config (no `MCP_API_BASE_URL`, dev-header without `MCP_ACTOR_ID`, or jwt with no credential path), matching the design's fail-fast rule. It never performs login. `api.ts` holds the token in memory only and the `onRequest` middleware sets exactly one identity header per request: `Authorization: Bearer` in jwt (only when a token exists), `X-Actor-Id` otherwise — never both. In jwt without a token yet, no header is sent and the backend's 401 drives the reactive path, as designed.

`callWithRelogin` retries once on 401 only when `canRelogin()` is true (the credentials path, vía b). Token-direct (vía a), dev-header, and no-credentials cases return the 401 unchanged, which `toMcpError` maps to an auth error. The login helper treats `result.error == null` as success (login returns 200), reads `expiresIn` but does not parse it, and types the response as `LoginResponseDto`. The login request body is the single documented exception to "no hand-written domain types," with a comment pointing to `login-request.dto.ts`.

### Error translation stays pure and leak-free

`toMcpError` is a pure function returning `null` on 2xx and mapping 400/401/403/404/409/422/5xx per the design table. It extracts a backend `message` defensively (string or Nest string[]) and never serializes the full error body; 5xx returns a generic message without the backend payload. `exceptionToMcpError` separates network failures (TypeError / ECONNREFUSED family, reported with the base URL only), zod validation (names the failing field), and unexpected errors (generic). No stack traces, secrets, or credential-bearing URLs reach the MCP content. All logging goes to stderr; stdout is reserved for the protocol.

### Tool surface: 1:1 with the contract

Every one of the 35 tools was checked against `openapi.json` and maps to a real route+method. Tools with no params declare an explicit `{}` input schema (serialized as `type: object`, confirmed by the smoke test — 0 tools without an object schema). Create/update bodies use `z.record(z.string(), z.unknown())` cast to the contract DTO, so the backend remains the sole domain authority. `health.check` is treated as public (no login trigger), `me.permissions` and `dev.actors.list` carry the configured identity, and `dev.actors.list` returns the neutral 404 message the design specified.

The `audit.events.list` `objectType` enum (`PROCESS, USER, GRANT, CATALOG_ITEM`) matches the contract and is protected by a bidirectional `Exclude`-based equivalence type exported as `EquivalenceGuard`, which fails `typecheck:mcp` if the contract's enum diverges. `take` is locally tightened to `z.number().int().positive().max(500)`, a documented stricter-than-contract shape constraint (the contract types it as plain `number`). A second local enum, `process.list` `kind`, matches the contract but has no such guard — noted above as a possible follow-up, not a defect.

### Root integration and the api-client ESM fix

Root `package.json` adds `build:mcp` and `typecheck:mcp` and appends mcp last to `build` and `typecheck`; `workspaces`, `db:*`, `test:unit`, `test:e2e`, `contracts:generate`, `docker:*`, and `dev:*` are unchanged. The api-client change adds explicit `.js` extensions to its two hand-written source files and switches its tsconfig to `nodenext`, required because the MCP is the first consumer to execute api-client's ESM output under Node (the frontend bundles it via Next and tolerated extensionless imports). This touches module resolution only, not the generated schema or any public signature, and the aggregate typecheck (including `apps/web`) passes.
